# Voice App - System Overview

This document provides a detailed overview of the **Voice App architecture**, which manages AI-driven phone call interactions for multiple use cases (Pre-sales, Post-sales, Dealer Campaigns, Inbound Calls, etc.). The system integrates with a voice provider, manages streaming between components, and orchestrates both AI and human agent handovers.

---

## 🧩 System Components

### 1. **Voice App Core**

Responsible for:

* Receiving jobs (Pre-sales, Post-sales, Dealer Campaign, Inbound)
* Generating dynamic prompts for the Voice Agent
* Creating calls via the voice provider
* Connecting the voice provider to the messaging server using a `session_id`
* Running **Input Manager** and **Output Manager** in parallel to manage real-time streaming

---

## 🎙️ Input Manager

Handles user audio input, manages AI agent states, and coordinates with the voice agent.

### Responsibilities:

1. Manage the **input stream** and queue.
2. Create a **unique message_id** for each user query and push it to the queue.
3. The Voice Agent polls the queue and sends response chunks with corresponding message_ids.
4. Streams AI responses to the Output Manager.
5. Manages the following **agent states**:

| **State**        | **Description**                                                                                                                                            |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Interruption** | When a new or follow-up query interrupts an existing one. Creates new `message_id`, cancels the current generation, and acknowledges/answers accordingly. |
| **Buying Time**  | While the AI generates a response, a **Filler Generator Agent** produces context-aware fillers to keep the conversation natural.                           |
| **Handover**     | When transferring to a human agent. Stops the Input Manager, maintains Output Manager only, and connects to socket server for live stream forwarding.      |
| **Idle**         | When the agent waits for user input. If idle beyond threshold, cancels processes and ends the call.                                                        |

### Fallback Handling

If the Voice Agent fails to generate a response, it sends the `message_id` to the **Agent Orchestrator**, which triggers the **Filler Generator Agent** to produce an appropriate fallback output.

---

## 🔊 Output Manager

Responsible for sending the AI or human agent’s response stream back to the voice provider.

### Responsibilities:

1. Connects to a shared queue and continuously polls for outgoing response chunks.
2. Sends streamed chunks to the voice provider for the active `message_id`.
3. If a new `message_id` is detected, stops current streaming and switches context.

### States to Manage:

| **State**       | **Description**                                                                       |
| --------------- | ------------------------------------------------------------------------------------- |
| **AI Agent**    | Default state. Streams responses for each `message_id` generated by the Voice Agent. |
| **Human Agent** | Activated during handover. Directly streams live audio from the messaging server.     |

---

## 🧠 Voice Agent

The AI-driven conversational engine responsible for real-time understanding and response generation.

### Responsibilities:

1. Generate responses and fillers based on the provided prompt.
2. If unable to generate a valid response, returns a **fillers list** and a **flag** indicating the need to escalate to the **Agent Orchestrator** with the same `message_id`.

## 🧩 System Flow Diagram



## ⚙️ Typical Flow

1. **Receive Job** → Identify type (Pre/Post-sales, Campaign, etc.)
2. **Generate Prompt** → Send to Voice Agent
3. **Create Call** → Voice Provider initiates outbound/inbound call
4. **Connect Session** → Messaging server bridges audio streams
5. **Start Managers** → Input + Output Managers handle stream
6. **Agent State Management** → Handle interruptions, handover, idle, etc.
7. **End Call** → On idle timeout or human handover completion

---

## 🧾 Summary

| **Component**      | **Key Role**                                             |
| ------------------ | -------------------------------------------------------- |
| Voice App Core     | Orchestrates job, prompt, call creation, and managers    |
| Input Manager      | Handles user input stream, interruptions, and idle state |
| Output Manager     | Streams AI/Human audio responses to provider             |
| Voice Agent        | Generates and manages AI conversation responses          |
| Filler Generator   | Produces contextual fillers during response latency      |
| Agent Orchestrator | Manages escalations and state coordination               |
| Human Agent        | Receives stream during live handover                     |
